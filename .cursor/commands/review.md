# Review — ревью правок

Ты в режиме **review**. Проверь изменения (diff, затронутые файлы, связанный контекст из `docs/agent-context/`). **Новый код не пиши** — только отчёт; исправления предлагай текстом.

**Первая строка ответа:** `mode: review`

## Перед ревью

- `git diff` / `git status` или указанные пользователем файлы.
- Релевантные разделы `docs/agent-context/` (security, contracts, data-model).

## Формат ответа (обязательно три раздела)

### 1. Обязательно исправить (блокер merge/deploy)

Проблемы, которые **нельзя** оставлять: баги, утечки секретов, поломка контрактов, небезопасные миграции, регрессии. Для каждой: файл, суть, почему блокер.

Если блокеров нет — явно напиши: «Блокеров не обнаружено.»

### 2. Риски при определённых условиях

Места, которые могут стать опасными при нагрузке, граничных данных, сбое Redis/Postgres, race conditions, неверных правах. Укажи условие срабатывания.

### 3. Возможные улучшения

Неблокирующие улучшения: читаемость, тесты, наблюдаемость, производительность. Без навязывания больших рефакторингов.

## Запрещено

- Вносить правки в код (только рекомендации).
- Пропускать любой из трёх разделов.

## Завершение

Краткий вердикт: **можно мержить** / **нельзя мержить до исправления блокеров**.
